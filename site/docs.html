Overview

Iron Rain is a native Apple app plus a lightweight Mac daemon. The daemon runs coding agents (claude-code, opencode, and more) on your Mac, against your code, using your subscriptions and keys. The iPhone/Mac app connects to it to watch sessions stream, steer them mid-run, review diffs, and approve sensitive tool calls — locally or from anywhere. Nothing runs in someone else's cloud; there is no per-seat compute and no middleman.

Install

Mac (app + daemon), one line:

curl -fsSL https://howlerops.github.io/iron-rain/install.sh | sh

This installs the Iron Rain Mac app and daemon and launches the app — no dependencies, no terminal to keep open. The app auto-starts the daemon, which auto-detects your installed agents and shows a pairing QR.

iPhone / iPad: Iron Rain for iOS is in beta via TestFlight — see joining the TestFlight.

Headless / Linux: the same command installs just the daemon and starts it (log at ~/.oculus/oculusd.log). It binds 0.0.0.0:6000 so the pairing QR carries a reachable address.

From source: cd daemon && go run . serve (Go 1.26+).

Pairing

When the daemon starts it prints (and shows in the app) a oculus://pair… QR code.

  1. Open the Iron Rain app and tap Scan QR code (or paste the oculus://pair… link under Enter details manually).
  2. The app stores the pairing (the daemon's public key + your secret) and reconnects automatically from then on — you only pair once.
  3. Pair as many Macs as you like: name each one and switch between them in the app.

The pairing secret is persisted at ~/.oculus/secret, so restarts and reinstalls keep an already-paired device authorized.

Remote access (from anywhere)

Iron Rain works off your home network with zero setup. Your daemon keeps an outbound connection to a shared, end-to-end-encrypted relay, and the app reaches your Mac through it when you're away — no port-forwarding, no inbound ports on your Mac. The relay only ever forwards ciphertext; it can't read your sessions.

On your home network the app connects directly over the LAN for the lowest latency, and falls back to the relay automatically when you leave — you never switch modes by hand. Prefer LAN-only? Start the daemon with --relay "".

Agents & providers

The daemon auto-detects the agents you already have installed and lists them in the new-session picker. Supported today:

  • claude-code — runs on your existing Claude subscription via a bundled sidecar (no API key needed; the daemon sets it up on first run). Supports plan mode.
  • opencode — the daemon auto-detects (or starts) a local opencode serve. Supports plan mode.
  • pi — detected on your PATH.
  • Generic CLI agents — codex, gemini, cursor-agent, aider, etc. are driven as terminal agents when they're installed and authenticated.

An agent only works if its own tool is installed and signed in. If a session produces an error like "codex exited: exit status 1" or an auth message, that's the underlying CLI — install/sign into it, or pick another agent. If starting a session with a provider fails (e.g. opencode isn't running), the app now tells you why instead of doing nothing.

What you can do

  • Lock-screen approvals — when an agent needs to run a sensitive tool, approve or deny it from a push notification, without unlocking into the app.
  • Heartbeat supervision — set a cost budget and let the daemon nudge a long-running agent to keep going, checkpoint, or escalate to you — and stop it before problems compound.
  • Plan mode — have the agent propose a plan you approve before it touches code (native agents).
  • Mid-run steering — interrupt and redirect an agent while it's working.
  • Mobile diff review — read the changes, and comment on a line to send that feedback straight back to the agent as a prompt.
  • Built-in IDE — a native file tree + syntax-highlighted editor with live LSP diagnostics, hover, and go-to-definition, scoped to the active session.
  • Cross-repo workspaces — run one agent across several repos on a shared oculus/<name> branch, and finish with a coordinated PR per repo.
  • Voice mode — talk to the agent hands-free; its replies are read back.
  • Fleet view — see every session across every paired Mac at a glance.

Integrations

  • Linear & Jira — connect a tracker (OAuth, or a token), browse assigned issues, and turn an issue straight into an agent session / PR.
  • Slack — mirror agent events (finished, needs approval, failed) to a channel via an Incoming Webhook (--slack-webhook or ~/.oculus/slack.json).
  • Push notifications — agent-finished / tests-failed / approval-needed alerts, tap-to-open the session.

Security model

  • End-to-end encrypted. The channel key is derived from X25519 ECDH between your app's and daemon's keypairs; traffic is sealed with ChaCha20-Poly1305. Neither the relay nor anyone on the network can read your sessions.
  • Your keys, your hardware. Code and credentials never leave your Mac. The daemon uses your Claude subscription / your API keys directly.
  • No inbound ports. The daemon dials out; nothing listens on the public internet. Files are only ever served within registered project roots and session working directories (with symlink-escape guards).
  • Secrets live at ~/.oculus/ with 0600 permissions.

Daemon reference

The daemon is oculusd. Start it with oculusd serve [flags]. The most useful flags:

--addrListen address (default 127.0.0.1:6000; the installer uses 0.0.0.0:6000 so the QR carries your LAN IP).
--relayComma-separated relay URLs for remote access (the app races them + LAN). Empty = LAN-only. Defaults to the shared HowlerOps relays.
--public-urlReachable base ws/wss URL to encode in the pairing QR (e.g. an ngrok tunnel). Defaults to a LAN URL derived from --addr.
--secretPairing secret clients must present. Omit to use the persisted ~/.oculus/secret.
--nameHuman name for this desktop shown in the app (default: hostname).
--opencodeURL of a running opencode serve (else auto-detected/started).
--piPath to the pi binary (else auto-detected on PATH).
--claude-setupclaude-code sidecar install when missing: ask | auto | off (default ask).
--slack-webhookSlack Incoming Webhook to mirror agent events (or set it in ~/.oculus/slack.json).
--apns-keyPath to an APNs auth key (.p8) to enable push, with --apns-key-id and --apns-team-id.

See all flags with oculusd serve --help.

Troubleshooting

Starting a session does nothing / shows an error. The selected agent's backend isn't available. opencode needs a running opencode serve (the daemon usually starts one — check it isn't blocked); codex/gemini/etc. must be installed and signed in. Pick an agent that's set up (claude-code works on your Claude subscription with no extra setup).

The daemon didn't start after install. The app shows a daemon status and a button to (re)start it. From a terminal: oculusd serve --addr 0.0.0.0:6000 (log: ~/.oculus/oculusd.log).

"Pairing rejected: unauthorized". The app is using a stale secret — re-scan the QR the daemon currently shows. The secret is persisted, so this usually only happens if ~/.oculus/secret was changed.

Can't connect when away from home. Remote access needs the daemon reachable via the relay — make sure the Mac is awake and the daemon is running (it reconnects to the relay on its own). On the same network the app uses the LAN directly.

"unknown type: …" after an update. An old daemon is still running. Re-run the installer (it stops the old daemon) or restart oculusd.
